## 续：修复"整个 3D 场景不渲染" + 玻璃材质重做（下午）

### 症状
首页 canvas 全黑，PRISM 文字排版正常但棱镜/光束/光谱全部不可见。控制台无报错，`onCreated` 正常触发，`gl.render()` 手动调用能画出 9 个 draw call（证明场景、几何、shader 都是对的），但 `useFrame` 从未执行过一次。

### 根因（关键教训）
`shaders/glassLamella.js` 与 `spectrumField.js` 里 `uTint` 的 uniform 值写成**普通 JS 数组** `[0.86, 0.9, 1.0]`，而 `GlassLamellae.jsx` / `SpectrumField.jsx` 在帧循环里调用 `u.uTint.value.set(...)`。数组没有 `.set()` 方法 → 第 1 帧抛异常 → **R3F 的内部 rAF 循环被永久杀死**，整个 WebGL 层静默变黑。

**规则：R3F 中所有 vec3 uniform 必须是 `THREE.Vector3` 实例，绝不能用普通数组。`useFrame` 内任何未捕获异常都会终止整个渲染循环，且不一定留下可见报错。**

### 排查方法（可复用）
1. `readPixels` 在合成后读 WebGL canvas 恒为黑，**不可用于判断是否渲染**，必须用截图。
2. 判断浏览器 GPU 是否可用：写一个最小 `gl.clearColor` 页面 → 能出色块说明 GPU 正常。
3. 判断 R3F 是否可用：写一个最小 `<Canvas>` + 旋转 cube + 帧计数 → 有帧数说明 R3F 正常，问题在自己的场景。
4. 在 `useFrame` 里累加 `window.__frames`，配合 `onCreated` 里手动 `gl.render()` 对比——可精确区分"场景错"和"循环死"。

### 玻璃材质：放弃 MeshPhysicalMaterial transmission
`transmission: 1.0` 采样的是**mesh 背后已渲染的场景内容**。纯黑页面背后什么都没有 → 玻璃折射"空"→ 退化成一层表面高光 → 看起来像乳白塑料。
试过加背景平面供折射：玻璃正常了，但背景平面自身对相机可见，页面上出现横条纹，破坏纯黑。

**最终方案**：新建 `shaders/prismGlass.js`，完全程序化合成光学效果，不依赖场景内容：
fresnel 边缘 + 每切面硬高光（flat normal，pow 220）+ 沿折射向量的 RGB 色散 + 内部 caustic 条纹 + 轮廓 rim。黑色保持纯黑，晶体通透锐利。

### 其他修复
- `main.jsx` 关闭 StrictMode（R3F 8.x dev 双调用会干扰 rAF 循环），并注明原因。
- `Scene.jsx` 拆分出 `OpticalSystem.jsx`（canvas 外壳与场景内容分离）+ 新增 `OpticalEnvironment.jsx`（程序化 canvas 环境贴图 + PMREM，零资源加载）。
- `store.js` 新增 `SECTION_LAYOUT`：每个 section 对应整个光学装置的空间位移（相机不动、光场重组，这是"用光完成转场"的实现机制）。
- 几何 `prismGeometry.js` 重做：横向 ring 从 10 减到 6（ring 过多会读成球体/线框球），只画竖向棱线 + 单条腰线；尺寸缩小给右侧光谱留空间。
- 光谱白团修复：`spectralRamp` 中央白色区间从 0.375–0.560 压缩到 0.488–0.512；新增 `emerge` 渐入（光必须先离开晶体才可见）；Bloom 阈值 0.14 → 0.34（加性混合下低阈值会把中间调糊成一片白）。
- 移除 `<Preload all />`（无 Suspense 边界时会挂起提交）。

### 验证结果
- 帧循环 486 帧 / 12 draw calls，控制台 0 错误。
- 五个 section 状态机全部生效：hero → converge(彩虹聚合成白光) → disperse(六色卡片) → orbit → ending(反向链条 SPECTRUM→REFRACTION→PRISM→LIGHT)。
- `npm run build` 通过：gzip 总计约 300KB（three 176KB + r3f 105KB）。

### 环境备注

## 续：补完项目视图与转场闭环（傍晚）

### 发现的缺口
第一阶段清单第 5/7 项（页面间转场、项目 placeholder）实际是断的：卡片能点、`store` 有完整 `project` 状态和转场 action，但 **`App.jsx` 里没有任何东西消费 `view === 'project'`** —— 点击后状态切了、页面什么都不显示。

### 修复的两个 bug

**1. 转场竞态（事件永远收不到）**
`openProject` 先 `set({transitioning:true})` 再**立刻** `window.dispatchEvent('prism:transition')`；而 `<Transition/>` 的监听器注册在 `useEffect([transitioning])` 里，effect 在事件派发之后才跑 → 事件发出时没有监听者 → 幕布永不启动。
**改为纯状态驱动**：store 持有 `curtainPhase / curtainColor / pendingView / pendingProject`，`<Transition/>` 只渲染状态并推进时间线。彻底删除 CustomEvent 机制。

**2. 可重入 effect 导致幕布卡死**
第一次改完后幕布停在屏幕上不消失（右半屏被橙色玻璃盖住）。原因：effect 依赖 `phase`，而 `commitPending()` 把 phase 从 `in` 改成 `hold` → effect 重跑 → cleanup 把自己的后续 timer 全 clear → 永远走不到 `out`。
**解法**：effect 只依赖 `transitioning`，用 `running` ref 保证一次转场只驱动一条时间线；cleanup 只在 `!transitioning` 分支和组件卸载时执行。

**通用教训**：用 `setTimeout` 串起来的动画时间线，绝不能让驱动它的 effect 依赖这条时间线自己会修改的 state，否则 cleanup 会自杀。

### 新增内容
- `sections/ProjectView.jsx`：项目详情页。Hero（index/wavelength/nm + 光带）+ 三个事实字段 + OVERVIEW/PROBLEM/PROCESS/OUTCOME placeholder + 图片槽位 + prev/next 波长导航 + Esc 返回。全部 placeholder，未编造任何内容。
- `styles/project.css`：独立文件（sections.css 已 855 行）。**零硬编码颜色**，全部走 `--spectrum-*` 变量，所以切换项目只换光、不换结构——直接实现"六个项目不是六个网站"。
- 转场幕布重做：从径向缩放（本质是 fade）改成**玻璃薄片横扫 + 彩色前缘**（`curtain-glass` + `curtain-edge`），扫入 → 驻留（DOM 交换）→ 扫出，同向不回头。含 reduced-motion 降级。
- `App.jsx`：按 `view` 切换 index/project，WebGL 层始终不卸载（保证"同一束光在重组"的连续感）；`useSectionObserver` 仅在 index 启用。
- `Nav.jsx` 修复：项目页里 index 的 section 已卸载，原本的 `scrollIntoView` 静默失效。改为先 `closeProject()`，再用 rAF 轮询等 index 挂载后滚动。
- 滚动记忆：`indexScrollY` 记录离开 index 时的位置，返回时在幕布不透明期间恢复（跳转不可见）；进入项目则从顶部开始。

### 验证结果（全部实测通过）

- prev/next 切换：tencent-news(ORANGE 605nm) → climbing-game(SKY BLUE 480nm)，版式完全一致、只有光变色。
- 返回索引：view=index、6 张卡片在、滚动恢复到 Work 区。
- 项目页点 Nav ABOUT → 回到 index 并定位到 About（y=577）、高亮正确。

## 续：参考 Oxyco 模板优化交互动效与质感（晚间）

### 参考站分析
`preview.yuanpu.cc/oxyco-portfolio-website-template`（Webflow 站，jQuery + Webflow scroll interactions，无 GSAP/Lenis）。提取到 4 个可迁移的**设计语言**（不复刻实现）：
1. 超大字重排版分层错落，视觉嵌在字层之间
2. 滚动时元素以不同速度移动（视差深度）
3. 文字逐词点亮（白色词渐次亮起，灰色词在后）
4. 满屏大字标题作为 section 间的"呼吸段"
5. 项目图片从大字标题背后升起并覆盖它 + 环境色外溢

### 新增能力
- `core/motion.jsx`：`useParallax()`（共享单个 rAF 循环，所有视差元素复用）+ `<SplitText>`（逐词遮罩上升，非淡入）。均支持 reduced-motion 降级。
- `styles/motion.css`：`.mega-title`（含 `is-outline` 描边 / `is-spectral` 波长渐变染色）、`.split-*`、`.rise`、`.rule-draw`、`.media-riser`。
- `base.css` 补齐缺失的 `.t-lead` / `.t-small` / `.t-micro`（之前 ProjectView 和多处用了 `t-small`/`t-micro` 但**根本没有定义**）。

### Hero 重构（效果提升最大）
改为参考站的分层错落大字：上层实心 `PRISM` + 下层描边 `SPECTRUM`（右偏移、负 margin 重叠），两层不同视差速度。
**关键修复**：棱镜原本被大字完全盖住 → 把 `SECTION_LAYOUT.hero` 的 x 从 0.30 改到 0.92，让晶体落在大字右侧留白区。现在完整光学叙事可读：白光左入 → 穿晶体 → 右侧散彩虹 → 被玻璃薄片切开，描边字让光穿透。

### 光学修复
- 彩虹右侧**矩形硬边**：`farFade`/`verticalSoft` 原在 travel=1.0 才归零，正好落在平面几何边界形成直角切口。改为提前收束（0.34→0.88），并新增 `edgeX * edgeY` 四边羽化兜底。
- 薄片**零散色块**：高度固定过高，超出光锥范围。改为 `height: 0.5 + t*1.1` 跟随光锥张开；shader 加 `vFade` 上下淡出。
- 背景偏蓝：`body::before` 的 navy 光晕 0.5/0.6 → 0.22/0.3，保住"70% 纯黑"。

### 放弃的方案（重要）
**手写 fake-scroll 惯性滚动**（translate 内容 + spacer 撑高度）：写完发现 rAF 循环怎么都不启动，且该方案会破坏所有 `position: fixed` 后代（nav、canvas、项目返回按钮），并让锚点/IntersectionObserver 的偏移计算变得歧义。
**结论**：删除，改用原生滚动 + `scroll-behavior: smooth`，质感靠视差、遮罩逐词动效、长缓动达成。已在 `motion.css` 顶部注明原因，避免以后重蹈。

- 卡片交错视差：相邻卡片 ±0.045 反向漂移 + 入场 stagger。
  - 坑：`.card-drift` wrapper 一开始写了 `grid-column: span 4`，但 `.project-grid` 实际是 **2 列**布局（`grid12` 被它覆盖），导致卡片占满整行。改为 `display: flex` 只占一格。
